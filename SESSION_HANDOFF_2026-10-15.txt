5. DECISIONS ON "NEW DOCUMENTS" (agreed in this session)
======================================================================
- Total documents = files that exist NOW. Deleted files not counted.
  Goes up and down.
- New documents   = files ADDED in a month/year, by file created date.
  Once a month ends its count is LOCKED. Deleted files still count as
  new in the month they were added.
- Picking one year: Total = everything up to end of that year,
  New = only that year.
- Picking All: New (all years) and Total can differ by the number of
  deleted files. That is correct.
- Source: Graph createdDateTime -> FileCreatedDate.
  Do NOT use Records.CreatedDate (that is the DECLARATION date and the
  Records table only has declared files).
- Skip folders.
- Copies/migrations count as new in the month they were copied.

How Dane should build it (storing every file is too heavy for him):
- Recommended: during the scan, read files per library using
    GET /drives/{DriveId}/root/delta?$select=id,name,createdDateTime,file,folder,size
  (EDRMSLibraries already has DriveId), count them by created month,
  and store ONLY totals: LibraryId | Month | NewFiles.
  Recalculate only the current month each refresh; past months locked.
- Simplest fallback: save site File Count from the usage report each
  month; new = difference. No history before go-live, net of deletes.
- Graph search counts: possible, NOT tested.
